# T-0765: live boot of the lab server against VM 119

**Result: the server did not boot; no session was minted and no E2E was run.** Nothing here is fabricated.

## What was run

- `lab/e2e/boot-lab-server.sh up` (lab build, PostgreSQL 16 container with the install roles and all
  migrations, `kek init`), with `WIN_LAB_DC_ADDR=192.168.1.9`, `WIN_LAB_TLS_NAME=dc1.win.activediq.test`,
  `WIN_LAB_CA` and `WIN_LAB_SVC_PASSWORD` taken from the main checkout's gitignored `lab/windows/` files.
  `main` at 54a2b458a (T-0783 sign-in path and `account init-local` present; T-0850 and T-0846 merged).
- The DC answered over verified LDAPS (signing + channel binding path): V5, V8 and V9 passed.

## What stopped it

```
server: lab bootstrap (win): activation refused (verdict failed; V7=not_run):
  connection: verification run did not complete: a pass does not answer every required check
```

The connector's verdict was `pass` with outcomes `V5=pass V7=warn V8=pass V9=pass`. `connection.checkResult`
(`internal/directory/connection/service.go`) requires V7 to be a clean `pass` for activation
(`passComplete`, `verification.go`), so a `warn` is recorded as an interrupted run and the connection
stays a draft. The service account is not the cause: all 8 V7 findings are
`exposure.tier0_broad_principal`, the enrolment extended right
`0e10c968-78fb-11d2-90d4-00c04f79dc55` granted to a broad principal on AD CS objects of the lab's own
enterprise root CA: the stock templates ClientAuth, Machine, IPSECIntermediateOnline, User, EFS,
UserSignature and Workstation, and the `activeDIQ Lab Root CA` enrollment service.

## Why this is a product question, not a lab fault

`internal/connector/rights/ad.go` documents this finding as "Warn, not block: it is the customer's ACL".
The server side treats it as a block: activation needs a clean V7 pass, and the Tier-0 override
(`connections.tier0_override.acknowledge`) acknowledges a V7 `fail`, so a `warn` has no way through. Any
customer running AD CS with default templates hits the same dead end. The lab bootstrap cannot work around
it without bypassing the gate, and weakening the lab DC's CA permissions would hide the defect from the
demo. Follow-up bug ticket filed (see the T-0765 notes).

## Cleanup

The container and the throwaway state under a temp directory were removed; temporary debug output used to
read the outcomes was reverted; no files in the product changed.
