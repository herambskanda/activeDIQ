## Run (2026-11-03, dc1 at 192.168.1.250, dc1 clock 06:08:14Z to 06:08:49Z)

One command, under the shared lock: `lab/windows/bin/with-dc1-lock lab/e2e/live-user-search.sh EVIDENCE_DIR` with `WIN_LAB_ENV` and
`WIN_LAB_CA` as absolute paths into the main checkout's gitignored `lab/windows/` files. It:

1. checks dc1 policy (`dc1-policy check`: signing 2, channel binding 2, clear-text bind of the service account refused with 8);
2. boots the lab-built server (`boot-lab-server.sh up`): the win connection activated at start-up (`lab connection active`), the API listens on TLS;
3. mints a session through the product's own sign-in API (`mint_session.py`: `account init-local`, password step, TOTP step; cookie in a 0600 temp file, never logged);
4. `web/e2e/live-user-search.spec.ts` types `lab-user-01` in the real console; the row `lab-user-01` (Enabled) is listed (`live-results.png`; the display-name and UPN cells are empty because the lab seed sets neither);
5. `dc1-evidence events <start>`: Directory Service events 2887, 3039, 3074 in the run window: 0 each (2889/3040/3041/3075 also 0);
6. `dc1-evidence svc`: svc-activediq has no direct group beyond its primary one and is not, recursively, in Domain Admins, Enterprise Admins, Schema Admins or Administrators (by SID).

Control (`dc1-events-control.txt`): the same query from 2026-10-01 reports 3039 x8 and exits 3, so the check sees real events and fails on them
(those are from before signing/channel binding were enforced, T-1265). The judges' failing and passing shapes are also unit-tested:
`python3 -m unittest lab/windows/tests/test_dc1_evidence.py`.

TLS stays verified end to end: Python verifies against the server's per-install certificate; Chromium pins that certificate's public key
(`--ignore-certificate-errors-spki-list`), not a blanket ignore.
