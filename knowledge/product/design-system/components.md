## DataGrid (T-0952)

One data grid for the results grid, library and schedules list. ARIA `grid` on a real `<table>`; rows are one line high (`--diq-row`, so compact/comfortable density follows `<html data-density>`).

- **Virtualised.** Only the rows in view plus 3 either side are in the DOM (about 22 for 12,000, 18 at the top); spacer rows keep the scroll height. Rows must have a stable `rowKey`. Do not put wrapping or variable-height content in a cell.
- **Sorting is the caller's.** `sortable` columns show `aria-sort`; click, Enter or Space on the header calls `onSort(key)` once. The caller owns the order (the server sorts) and passes `sort`. Sort changes are announced politely ("Sorted by Name, ascending").
- **Sizing.** `width` is in characters (`ch`, default 16). `resizable` adds a pointer drag handle and Shift+Left/Right on a focused header (step 2 ch, 6 to 120 ch); `onColumnResize` lets the screen persist widths. The grid is as wide as its columns; spare room stays empty.
- **Row header and sideways scroll (T-1516).** The first column is the row header (`th scope=row`) and, with the selection column, stays in view when scrolling sideways (the name column). While scrolled, a rule on its inline end shows content tucked behind it (`data-scrolled-x`). Arrowing onto a cell that is behind that column or past the far edge scrolls it into view (LTR and RTL; `inlineShift` is the tested rule). Put the name there and keep it first.
- **Beside a detail pane (T-1516).** `currentRowKey` marks the row the pane shows (`aria-current`, signal tint, a bar on its first cell) and scrolls it into view when it changes, without moving focus. `onActiveRowChange(row)` fires when focus lands on a different data row (arrows, Tab in, click; never the header), so the pane can follow. `onEscape` is Escape on a cell, for closing the pane.
- **Truncation.** Cells truncate with an ellipsis and carry the full text in `title`: automatic for string and number cells, pass `title` when the cell renders a component.
- **Selection.** On when `onSelectedChange` is given; `selected` is a set of row keys. Click the checkbox cell, Space on a row, Shift+click or Shift+Space for a range, Ctrl+A for all rows loaded, header checkbox for all (indeterminate when partial). Selection is of loaded rows: server-wide "select all 12,431" is the screen's banner, not the grid's.
- **Keyboard.** One tab stop. Arrows move between cells (mirrored in RTL), Home/End row ends, Ctrl+Home/Ctrl+End grid corners, PageUp/PageDown a page. Enter on a cell with a link or button moves into it (Tab reaches widgets only from their own cell; Escape returns to the cell); Enter on a plain cell calls `onRowActivate`.
- **States.** `busy` (`aria-busy`, progress cursor, signal rule under the header; never dimmed, so contrast holds), `empty` slot, focus ring inset on the cell, hover and selected row backgrounds on tokens that are in the contrast test. Dark and light both.
- **Not yet:** column reorder and hide (the screen's Columns popover owns visible columns today), group rows, inline editing, server paging (B12a: pass `rows` as they load).

## Form controls (T-0954)

Select, Checkbox, RadioCardGroup, SegmentedControl and TokenInput share one contract, so a form built from them behaves the same everywhere.

- **Controlled, one callback.** Each takes `value`/`checked` and reports the new value (`onChange(value)`), not an event. No internal selection state; TokenInput keeps only the typed text (pass `query` to own it).
- **Visible label, always.** `label` is required and visible (a `legend` for the two choice groups). `error` sets `aria-invalid` and is linked with `aria-describedby`, after the `hint`; on the choice groups the description sits on the `radiogroup`.
- **Native underneath.** Select is a `<select>`; Checkbox and the choice groups are real checkbox and radio inputs. The browser supplies Space/arrow behaviour and form participation. Tab enters a radio group once; arrows move and select.
- **Clearing.** Select: the `placeholder` option. Checkbox: untick. Choice groups: `clearable` adds a Clear button (only once something is chosen; focus stays in the group); `onChange(null)`. TokenInput: Backspace in an empty field removes the last token, each token has a Remove button, Escape clears the text.
- **State matrix.** default, hover, focus-visible, disabled, error, read-only (`readOnly`: focusable and announced, cannot change; Select shows its value in a read-only field), loading (Select, TokenInput), selected/checked. Both themes; every colour pair is in `tokens.test.ts`.
- **Long values.** Labels truncate with the full text in `title`; tokens and options truncate, with `detail` as the tooltip. Logical properties throughout, so right-to-left names lay out correctly.

### TokenInput

- **Keyboard.** Typing calls `onQueryChange`; the caller answers with `suggestions` (ids already chosen are filtered out). Up/Down move through them (wrapping), Enter picks. Enter, comma or semicolon, and leaving the field commit typed text through `parse`; `parse` returns null to refuse it (the text stays). Without `parse`, only suggestions can become tokens. Escape closes the list, then clears the text, and only then lets the key reach a surrounding sheet.
- **Announcements.** One polite status region: "Searching…", "3 suggestions", "No matching accounts" (`emptyText`), "Added X", "Removed X".
- **Not decided here.** What counts as a valid recipient, the maximum count and domain rules belong to the screen: put them in `parse`, `error` and `Token.invalid`/`badge` (the badge is words, never colour alone).

## Overlays (T-0953)

Popover, PopoverMenu, SideSheet and Toast replace the reports prototype's local menu, sheet and toast CSS. Stories: `src/ds/components/overlays.stories.tsx`; interaction and axe tests: `overlays.test.tsx`.

- **Trigger.** `trigger={(p) => <Button {...p}>Export</Button>}`. Spread `p` on a `<button>`: it carries the ref (focus returns there), `aria-haspopup`, `aria-expanded`, `aria-controls`, the click toggle and, for a menu, Arrow Down/Up to open. To react to the click too (analytics), wrap `p.onClick` rather than replacing it. Open state is uncontrolled by default; pass `open`/`onOpenChange` when a screen coordinates several popovers or opens one from a shortcut key.
- **PopoverMenu keys.** Focus goes to the first available item on open. Arrow Up/Down move (wrapping), Home/End jump, Enter/Space/click invoke. An item's one-character `accelerator` invokes it from anywhere in the open menu (case-insensitive; ignored with Ctrl, Alt or Meta). That is why there is no type-ahead. Choosing closes the menu and puts focus back on the trigger **before** `onSelect` runs, so a sheet the item opens restores focus to the trigger in turn. Escape and Tab close it too (Tab parks focus on the trigger). A press outside, or focus moving away, closes it and leaves focus where the user put it.
- **Disabled items** are `aria-disabled`: still focusable and readable, never invoked (not by click or accelerator), menu stays open. Say why in `description` ("limit 100,000 rows"); give a longer explanation a `role="alert"` of its own in `footer`.
- **Popover** is a non-modal `role="dialog"` named by `label`. First control takes focus (mark another with `data-autofocus`). Same close rules as the menu.
- **Placement.** Panels open below the trigger, lined up with its start or end edge (`align`), mirrored in RTL. They are not portalled and do not flip at the viewport edge: put end-aligned triggers on the right side of a toolbar. They stay inside a SideSheet's focus trap.
- **SideSheet.** Modal, from the inline-end edge. While open: focus is trapped (Tab and Shift+Tab wrap; stray focus is pulled back), everything else on `body` is `inert` (a `ToastRegion` is exempt so announcements still arrive), Escape, the Close button and a click on the scrim (press and release both on it, so a drag from inside never closes) call `onClose` (the caller may confirm unsaved work), and on close focus returns to the element that had it when the sheet opened. Initial focus: an `autoFocus` or `data-autofocus` control, else the first tabbable (Close). Children own their layout; put the `<form>` and its submit button inside. It leaves instantly (no exit animation). The slide-in uses `--diq-dur`, which is 0 under reduced motion.
- **Toast.** Lives in a `ToastRegion` (`role="status"`, `aria-live="polite"`), a persistent region on `body`, so a toast that arrives later is announced politely without taking focus. Mount the region once per screen and render at most one `Toast` in it. Nothing times out (WCAG 2.2.1); it stays until dismissed or replaced. The action calls `onAction` once and then `onDismiss`; if the toast held focus when it unmounts, focus returns to where the keyboard user came from, not the page. While a SideSheet is open the toast action is outside the focus trap: raise toasts that need the action after the sheet closes.
- **Tokens.** New with this ticket: `--diq-z-popover`, `--diq-z-sheet`, `--diq-z-toast` (layers), `--diq-scrim` (the existing prototype value, 35 % black, both themes), `--diq-sheet-w-wide`, `--diq-popover-w`, `--diq-toast-w`.
- **Not yet:** flipping/portalled popovers, nested submenus, checkbox and radio menu items, multiple stacked toasts, an exit animation.

## Command palette (T-1098)

`CommandPalette` is presentational: the console owns the query, debounces, calls the search API and passes `status` and `groups`; the component fetches and routes nothing (information-architecture §5). Stories (fixtures live only there and in the tests): `src/ds/components/command-palette.stories.tsx`; tests: `command-palette.test.tsx`.

- **Structure.** A modal `role="dialog"` named by `label`, holding an ARIA 1.2 combobox (the input) that controls a `listbox` of labelled `group`s of `option`s. Focus never leaves the input: the highlighted row is `aria-activedescendant` and `aria-selected`. The page behind is `inert` and focus returns to the opener on close (the same `useModalLayer` as `SideSheet`).
- **States (`status`).** `idle`: empty query, `groups` hold recent, pinned and suggested items. `loading`: skeleton (the caller shows it after its 300 ms budget). `results`: `groups` answer the query; none at all is "No results for “…”" (override with `notice` to name scope and suggest next steps). `error`: alert, plus "Try again" with `onRetry`. `denied`: the input is read-only and `aria-disabled`; say why in `notice`.
- **Keys.** `usePaletteShortcut` binds Ctrl/⌘+K anywhere and `/` outside fields; bind it once in the shell. In the palette: Up/Down move the highlight (wrapping), Home/End jump to the first and last row (so they do not move the caret), Enter runs the row, Right with the caret at the end calls `onExpand` for an `expandable` row (the caller swaps `groups` for the object's action list), Escape closes. Tab and Shift+Tab stay in the dialog: with only the input they do nothing; an error notice's buttons join the cycle. Typing resets the highlight to the first row. Keys are ignored during IME composition. A row press does not move focus.
- **Rows.** `typeTag`, `name` (query words highlighted with weight as well as colour), mono `identifier`, status `chips` (words always; warn and crit add a glyph), `disambiguator`, `dn` truncated in the middle (full value in `title`, shown whole on the highlighted row, and read in full by screen readers) and `domain`. Everything is a text node: names, DNs and hostile markup never become HTML. Long unbroken text wraps. A `disabled` row stays listed with `disabledReason` and is never run. A group with `total` above its `items` ends in a "Show all N" row when `onShowAll` is set. Group headings show `total` when given ("in your scope").
- **Announcements.** A polite status region says "N results, M groups" (or "No results") once the result set has been steady for `announceDelay` (400 ms); idle, loading and error say nothing there (the error is its own alert). Override the wording with `announce` for localisation.
- **Tokens.** New: `--diq-palette-w` (640 px), `--diq-palette-list-h` (400 px, then the list scrolls), `--diq-z-palette` (15: over a sheet, under toasts). The only new colour pair is secondary text on the highlighted row, added to `tokens.test.ts`. The entry fade and rise use `--diq-dur`, which is 0 ms under reduced motion.
- **Not yet:** streaming results by group, `>` actions-only mode and the 5-minute query memory (screen logic), the dashed "Deleted" chip, a per-row action sub-list inside the component.

## DetailDock, DeltaCell, PinnedBand (T-1516)

Specified in [reports-2-second-slice-screens.md §8](reports-2-second-slice-screens.md). Stories: `detail-dock.stories.tsx` and `delta-pinned.stories.tsx` (fixtures invented). Screenshots of every story: `components-shots/T-1516/`.

**DetailDock.** A docked, non-modal pane beside the grid, in `DockLayout` (side by side while the width allows, below the grid at full width otherwise: it wraps on `--diq-sheet-w`, no breakpoints).

- **Wiring (the screen's job).** Row in the URL (`?row=`). `DataGrid`: `onRowActivate` opens, `onActiveRowChange` sets the row while the dock is open, `currentRowKey` shows it, `onEscape` closes. `DetailDock`: `onPrev`/`onNext` and `position` for the pointer. The component keeps no row state.
- **Focus.** Opening moves no focus: the admin keeps pressing ↑/↓ in the grid and the pane follows (0 interactions per further row). Tab reaches the dock after the grid. Esc inside the dock closes it and, if focus was lost with it, returns to what had focus when the dock opened (nothing to return to when opened by a deep link). It is an `aside` labelled by its title: not a dialog, no trap, the page behind is live.
- **Announcements.** On open, and when Previous/Next changes the row while focus is in the dock: "Name, 5 of 214" (polite). Grid-driven changes are not announced twice: the grid announces its own row.
- **Prev/Next at the ends** are `aria-disabled` (not `disabled`), so stepping onto the last row does not drop focus to the page.
- **Long content.** Title, description and body wrap anywhere (64-character names, DNs, RTL); the body scrolls inside the dock; a new row starts at the top.
- **States.** Default, first row, last row, long title, RTL (dock on the inline end), dark, narrow (wrapped below). Close, Previous and Next have hover, focus-visible and aria-disabled.
- **Not for** a Save (use `SideSheet`) or a quick choice.

**DeltaCell.** `value`, a glyph and a signed number: `▲ +12` stricter, `▼ −2` weaker, `=` same, `≠` differs. The direction is the screen's (it is domain knowledge: a longer lock-out is stricter, "never expires" is the loosest); when `ad-expert` has not confirmed one, pass `differs`. Only `weaker` is coloured (warn); stricter is plain text, never green, because stricter is not better. A visually hidden sentence ("stricter than the domain policy, +12") replaces the glyph for assistive technology; `showWord` adds the word for a detail pane. In a grid cell pass `title` on the column (the cell is a component).

**PinnedBand.** A `group` above a `DataGrid`, outside the table, so sorting, scrolling and virtualising never move it. Not `role=rowgroup`: ARIA requires that inside a table or grid. Renders nothing for zero items. Shows `limit` items then "Show N more" (`aria-expanded`); expanded, the list scrolls and is a tab stop. Tone is glyph (✕ ⚠ ⓘ) + words + tint, as `Banner`. Items are free content: the band does not align to the grid's columns.

Contrast: every new colour pair (warn on hovered/current row, secondary text and links on the pinned tints) is in `tokens.test.ts`. No token was added or changed.
