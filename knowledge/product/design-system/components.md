## DataGrid (T-0952)

One data grid for the results grid, library and schedules list. ARIA `grid` on a real `<table>`; rows are one line high (`--diq-row`, so compact/comfortable density follows `<html data-density>`).

- **Virtualised.** Only the rows in view plus 3 either side are in the DOM (about 22 for 12,000, 18 at the top); spacer rows keep the scroll height. Rows must have a stable `rowKey`. Do not put wrapping or variable-height content in a cell.
- **Sorting is the caller's.** `sortable` columns show `aria-sort`; click, Enter or Space on the header calls `onSort(key)` once. The caller owns the order (the server sorts) and passes `sort`. Sort changes are announced politely ("Sorted by Name, ascending").
- **Sizing.** `width` is in characters (`ch`, default 16). `resizable` adds a pointer drag handle and Shift+Left/Right on a focused header (step 2 ch, 6 to 120 ch); `onColumnResize` lets the screen persist widths. The grid is as wide as its columns; spare room stays empty.
- **Row header.** The first column is the row header (`th scope=row`) and, with the selection column, stays in view when scrolling sideways. Put the name there.
- **Truncation.** Cells truncate with an ellipsis and carry the full text in `title`: automatic for string and number cells, pass `title` when the cell renders a component.
- **Selection.** On when `onSelectedChange` is given; `selected` is a set of row keys. Click the checkbox cell, Space on a row, Shift+click or Shift+Space for a range, Ctrl+A for all rows loaded, header checkbox for all (indeterminate when partial). Selection is of loaded rows: server-wide "select all 12,431" is the screen's banner, not the grid's.
- **Keyboard.** One tab stop. Arrows move between cells (mirrored in RTL), Home/End row ends, Ctrl+Home/Ctrl+End grid corners, PageUp/PageDown a page. Enter on a cell with a link or button moves into it (Tab reaches widgets only from their own cell; Escape returns to the cell); Enter on a plain cell calls `onRowActivate`.
- **States.** `busy` (`aria-busy`, progress cursor, signal rule under the header; never dimmed, so contrast holds), `empty` slot, focus ring inset on the cell, hover and selected row backgrounds on tokens that are in the contrast test. Dark and light both.
- **Not yet:** column reorder and hide (the screen's Columns popover owns visible columns today), group rows, inline editing, server paging (B12a: pass `rows` as they load).

## Form controls (T-0954)

Select, Checkbox, RadioCardGroup, SegmentedControl and TokenInput share one contract, so a form built from them behaves the same everywhere.

- **Controlled, one callback.** Each takes `value`/`checked` and reports the new value (`onChange(value)`), not an event. No internal selection state; TokenInput keeps only the typed text (pass `query` to own it).
- **Visible label, always.** `label` is required and visible (a `legend` for the two choice groups). `error` sets `aria-invalid` and is linked with `aria-describedby`, after the `hint`; on the choice groups the description sits on the `radiogroup`.
- **Native underneath.** Select is a `<select>`; Checkbox and the choice groups are real checkbox and radio inputs. The browser supplies Space/arrow behaviour and form participation. Tab enters a radio group once; arrows move and select.
- **Clearing.** Select: the `placeholder` option. Checkbox: untick. Choice groups: `clearable` adds a Clear button (only once something is chosen; focus stays in the group); `onChange(null)`. TokenInput: Backspace in an empty field removes the last token, each token has a Remove button, Escape clears the text.
- **State matrix.** default, hover, focus-visible, disabled, error, read-only (`readOnly`: focusable and announced, cannot change; Select shows its value in a read-only field), loading (Select, TokenInput), selected/checked. Both themes; every colour pair is in `tokens.test.ts`.
- **Long values.** Labels truncate with the full text in `title`; tokens and options truncate, with `detail` as the tooltip. Logical properties throughout, so right-to-left names lay out correctly.

### TokenInput

- **Keyboard.** Typing calls `onQueryChange`; the caller answers with `suggestions` (ids already chosen are filtered out). Up/Down move through them (wrapping), Enter picks. Enter, comma or semicolon, and leaving the field commit typed text through `parse`; `parse` returns null to refuse it (the text stays). Without `parse`, only suggestions can become tokens. Escape closes the list, then clears the text, and only then lets the key reach a surrounding sheet.
- **Announcements.** One polite status region: "Searching…", "3 suggestions", "No matching accounts" (`emptyText`), "Added X", "Removed X".
- **Not decided here.** What counts as a valid recipient, the maximum count and domain rules belong to the screen: put them in `parse`, `error` and `Token.invalid`/`badge` (the badge is words, never colour alone).
