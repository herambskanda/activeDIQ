# AD lab — procedures

Provisional until ADR-0001 and the first lab ticket (`ops`, owner `devops-engineer`, with
`test-engineer`). When the lab exists, its runbook moves to
`knowledge/development/runbooks/ad-lab.md` and this file points there.
Samba reference: https://wiki.samba.org/index.php/Setting_up_Samba_as_an_Active_Directory_Domain_Controller

## 1. Samba image

- Our own image in `lab/samba/` (Debian stable + `samba`, `winbind`, `krb5-user`, `ldb-tools`),
  pinned by digest. Samba is GPLv3: it is **test infrastructure only**, never shipped — record it
  in the licence register as test-only.
- Works on Apple Silicon (linux/arm64) and x86-64 CI runners. Needs `cap_add: [SYS_ADMIN]` for
  extended attributes on sysvol; use `privileged` only if that proves insufficient, lab only.
- Ports mapped to the host: 636 (LDAPS), 3269 (GC over TLS), 88 (Kerberos), 389 (only for
  StartTLS and signing tests).

## 2. Provision (first run of a tier)

```bash
samba-tool domain provision --server-role=dc --dns-backend=SAMBA_INTERNAL --use-rfc2307 \
  --realm=LAB.ACTIVEDIQ.TEST --domain=LAB --adminpass="$LAB_ADMIN_PASSWORD"
samba -i   # foreground; container health check = LDAPS bind as the lab service account
```

- `$LAB_ADMIN_PASSWORD` is generated by `make lab-up` into `lab/.lab.env` (gitignored).
- Samba generates a self-signed TLS certificate; `lab-up` exports its CA to `lab/.lab-ca.pem`.
  Tests trust that CA; nothing skips verification.
- Default Samba requires strong auth (no simple bind over plain LDAP) — keep it; it matches
  hardened customer DCs.
- Create the **lab service account** the product uses, with delegated rights only on
  `OU=Managed,DC=lab,DC=activediq,DC=test` — never Domain Admins — so permission errors show up in
  tests the way they will at customers. A separate admin identity is used only by seeding.

## 3. Seed

- `lab/seed/generate --tier <small|scale|demo> --seed <n>` emits LDIF deterministically
  (fixed seed, fixed name lists, `@example.com`). Seed version = generator version + seed.
- Load into the **stopped** provisioned database with `ldbadd -H /var/lib/samba/private/sam.ldb`
  (much faster than per-user `samba-tool` calls), then start Samba. Passwords as
  `unicodePwd::` base64 of the quoted UTF-16LE value. Timings for `scale` are `[UNVERIFIED]` —
  record them in the runbook once measured.
- States that cannot be written directly are produced through the protocol after start:
  lockouts by failed binds up to the threshold; `lastLogon` by real binds; must-change by
  `pwdLastSet=0`.

| Tier | Contents |
| --- | --- |
| `small` | ~500 objects: 3-level OU tree, 300 users across states, 60 groups (nested, one cycle, one 3,000-member group via generated members), 50 computers, every edge-case name |
| `scale` | 50,000 users, 5,000 groups, 500 OUs, 10,000 computers; realistic distributions of state and membership |
| `demo` | Curated, believable synthetic organisation for milestone demos (`demo` skill); loaded only into demo environments |
| `2dc` | `small` + a second DC joined with `samba-tool domain join … DC` for per-DC attribute, USN and replication tests |

## 4. Snapshot and reset

- After seeding: stop Samba, tar `/var/lib/samba` and `/etc/samba` into
  `lab/.snapshots/<tier>-<seedversion>.tar.zst` (gitignored; cached in CI by key).
- `make lab-reset`: stop, restore the tar, start — seconds, not minutes.
- Between test suites: reset. Within a suite: each writing test uses its own OU and removes it.
- A changed generator or seed changes the snapshot key; stale snapshots are never reused.

## 5. Windows lab (requires an answered CEO decision)

Needed for: Security event log collection (e.g. 4720 user created, 4738 changed, 4740 locked out,
4625 failed logon, 5136 directory object modified), audit policy, GPO processing and reporting,
DC agent and password filter (runs in LSASS), credential provider, ADWS/PowerShell module, real
Windows diagnostic strings, LDAP signing and channel-binding enforcement, Windows LAPS, Recycle
Bin, multi-domain forests and trusts.

Options to present in the decision (costs researched at the time, sourced): cloud VMs (e.g. Azure
or AWS Windows Server images, billed hourly; shut down when idle), or Windows Server evaluation
images on x86-64 hardware we own (licence terms apply). Apple Silicon Macs cannot run x86-64
Windows Server natively. Infrastructure as code in `lab/windows/`; credentials in the OS keychain
or the CI secret store; the environment is torn down or stopped when not in use.

## 6. Entra test tenant (requires an answered CEO decision or action)

- A dedicated test tenant — never a production, customer or partner tenant. P1-dependent features
  (`signInActivity`) need a licence or trial; say which in the decision.
- App registration per environment with certificate credentials and least-privilege application
  permissions (`ad-engineering` §5). Tenant ID and certificate in the keychain / CI secrets.
- Seed through Graph with the same deterministic generator (`--target entra`), tagged so cleanup
  can find every object. Respect throttling during seeding.
- Unit tests use recorded, sanitised HTTP fixtures; live tests run nightly and are tagged
  `entra-live`.
